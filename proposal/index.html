작업과 작업허가는 상태 머신으로 순서를 강제합니다

배정된 작업자 전원의 확인과, 허가 대상 작업의 유효한 허가 승인이 모두 갖춰져야 작업 시작을 승인할 수 있습니다. 허가 대상·승인 주체·유효 조건은 G1에서 확정하며, 모든 전이는 수행자·시각·IP와 함께 이력으로 남습니다.

모든 데이터를 소속으로 묶고 서버에서 분리합니다

서버가 인증된 사용자에게 허용된 고객사·현장·협력업체 범위를 적용하는 공통 접근 제어 계층을 거치게 합니다. 협력업체 계정은 자기 회사의 신청·작업자만, 작업자는 자신에게 배정된 작업만 볼 수 있습니다. 권한 없는 자료 요청은 거부하고 감사 로그에 남깁니다.

작성 중 임시저장에는 필수값 누락을 허용하되 입력된 값의 형식을 검사합니다. 제출·확인 단계에서는 필수 항목과 확인 권한을 서버에서 모두 검증합니다. 보수작업 신청서·명단·위험성평가의 확인은 작업허가 심사에 연결하고, 검토·승인 담당과 순서는 G1 권한표에서 확정합니다.

  • 서류 1건 → 엑셀 — 항목 표 형식(정의서 순서 그대로)으로 즉시 생성합니다. 대표 1종은 원본 서식(병합 셀 · 결재란)을 재현합니다.
  • 기간 · 현장 · 양식 조건 → 파일 묶음(ZIP) — 서류 엑셀 + 첨부 사진을 폴더 구조(현장/양식/날짜_서류번호/)로 묶습니다. 시간이 걸리므로 백그라운드 작업으로 만들고, 완료되면 화면 알림과 함께 만료형 다운로드 링크를 제공합니다.
  • 내려받기 이력(누가 · 언제 · 어떤 조건으로)을 남겨, 서류가 외부로 나간 경로를 추적할 수 있습니다.

7-5 작업자 모바일 안전 확인 — 사고와 직결되는 흐름

작업자가 앱 설치 없이 알림톡 링크로 진입하고 합의한 확인 절차를 거쳐 안전 내용을 확인합니다. 필수 확인을 건너뛰지 않도록 단계별 조건과 기록을 서버에서 검증합니다. 화면상의 확인 기록은 실제 보호구 착용이나 현장 안전 상태를 직접 검증하는 수단이 아니며, 현장 점검과 병행합니다.

단계작업자 화면시스템이 강제하는 것
① 진입알림톡의 [작업 확인하기] 링크를 누름작업자·작업별 만료형 서명 링크의 서명·유효기간·취소·현재 배정 상태 검사. URL의 작업자·작업 ID를 바꿔 접근하면 거부
② 간편 확인기본안: 휴대전화번호 뒤 4자리 입력5회 틀리면 해당 링크 잠금, 작업관리자에게 표시. 일회용 인증번호 등 추가 인증은 계약 전 합의한 방식 적용
③ 작업 내용 확인작업 위치 · 위험 요인 · 보호구 · 안전 수칙항목은 양식 엔진으로 정의(작업 종류별로 다른 점검 항목 가능)
④ 안전 점검 체크항목마다 「확인」 체크, 필요 시 사진 첨부필수 항목을 모두 체크해야 [개인 승인] 버튼이 활성화되고, 서버에서도 같은 조건으로 다시 검사
⑤ 개인 승인[안전 확인 완료]확인한 작업·안전 내용의 버전과 확인 시각 · IP · 기기 정보를 저장. 현재 배정된 전원의 유효한 확인 전에는 작업 시작 승인 거부
⑥ 작업관리자 승인(작업관리자 화면) 전원 확인과 작업허가 상태를 보고 승인G1 권한표상 해당 협력업체·작업의 승인 권한을 가진 작업관리자만 처리할 수 있으며, 허가 대상 작업은 유효한 허가 승인까지 확인한 뒤 「작업 중」으로 전환
⑦ 완료 보고완료 사진 · 특이사항 입력 후 [작업 완료]사진은 업로드 시 축소 저장. 작업관리자가 완료를 확인하면 종료
  • 카카오톡 인앱 브라우저에서 열리는 것을 기본으로 설계하고, 큰 글씨 · 큰 버튼 · 한 화면 한 단계로 구성합니다. 현장에서 장갑을 낀 채 누를 수 있는 크기를 기준으로 합니다.
  • 확인 기록은 수정할 수 없고, 잘못 확인한 경우 작업관리자가 「재확인 요청」을 보내 새 기록을 남기는 방식으로만 바로잡습니다.
  • 뒤 4자리 확인은 간편 확인이며 실제 신원을 보장하지 않습니다. 링크와 번호가 함께 공유되면 대리 확인이 가능하다는 한계를 계약 전에 안내하고, 추가 인증은 요구 수준과 공수·서비스 이용료를 확인해 승인 후 반영합니다.
  • 확인 대상이 바뀌면 다시 확인받습니다. 작업자·위험 요인·보호구 등이 바뀌면 영향을 받는 확인·시작 승인을 무효화하고 변경 버전의 재확인을 요구합니다. 허가 조건 변경·취소 시에는 해당 허가도 재검토하며, 기존 이력은 보존합니다. 작업 중 변경은 임의로 상태를 초기화하지 않고 재개 승인 전 완료 보고 외의 진행 처리를 차단하며, 중지·재개 절차는 G1에서 확정합니다. 링크 재발급·배정 취소 시 기존 링크를 폐기하고, 중복 확인 요청은 한 건으로 처리합니다.

7-6 협력업체 작업허가 — 쿠폰 발행 승인 워크플로와 같은 구조

  • 협력업체가 모바일 웹 또는 PC에서 보수작업 신청서·작업자 명단·위험성평가를 작성·첨부해 작업허가를 신청합니다. 작업 일시·위치·내용·위험 요인 등을 양식 엔진으로 관리하며, 안전관리자와 G1에서 정한 승인 담당자가 검토합니다.
  • 신청 → 검토 중 → (보완 요청 → 재신청) → 승인 / 반려로만 넘어가며, 보완 요청과 반려에는 사유 입력이 필수입니다. 재신청 시 이전 신청본을 그대로 보존하고 새 차수로 저장해 차수별로 비교할 수 있습니다.
  • 승인된 작업허가는 허가 번호·승인 차수를 작업에 연결합니다. 허가 대상 작업은 시작 승인 시 허가의 승인·유효기간·취소·변경 여부를 서버에서 검사하며, 결과는 알림톡으로 협력업체 담당자에게 발송됩니다.

그 밖의 필수 과업

  • 역할 5종(관리자 · 작업관리자 · 안전관리자 · 협력업체 · 작업자)을 권한표(역할 × 기능 × 조회/등록/승인 × 허용 소속 범위)로 정의하고 G1 산출물로 확정합니다. 공고의 「업체 작업관리자」가 어느 소속에서 어느 협력업체·작업을 승인하는지 명시하고, 승인 API에서도 역할과 소속 범위를 함께 검사합니다.
  • 관리자·작업관리자·안전관리자·협력업체는 아이디·비밀번호 로그인(비밀번호는 단방향 해시로 저장, 5회 오류 시 잠금), 작업자는 알림톡 링크 + 합의한 확인 방식으로 들어옵니다. 조회·수정·내려받기는 공통 접근 제어 계층을 거칩니다.
  • 고객사 → 현장 → 협력업체 → 작업자의 소속 계층으로 관리하고, 협력업체는 「현장별 출입 협력업체」로 따로 연결합니다. 작업자는 이름 · 휴대전화번호 · 소속 협력업체 · 직종 · 안전교육 이수일을 관리하고 엑셀 일괄 등록(오류 행 표시 후 정상 행만 등록)을 제공합니다.
  • 안전교육 유효 기간이 지난 작업자는 배정 화면에서 경고 표시합니다. 배정 차단까지 할지는 G1에서 정합니다.
  • 작업관리자가 작업(현장 · 위치 · 작업 종류 · 위험 작업 여부 · 예정 일시 · 협력업체 · 작업자)을 등록하고 배정합니다. 배정을 확정하는 순간 알림톡 발송이 요청되며, 상태가 바뀔 때마다 수행자 · 시각 · 이전/이후 상태가 이력에 쌓입니다.
  • 대시보드는 상태 카드 · 목록 · 필터 중심입니다 — 오늘의 작업, 작업자 확인 대기, 작업관리자 승인 대기, 긴급작업, 현장별 진행률, 차트 2종.
  • 알림톡 발송 시점은 작업 배정, 작업허가 결과(승인 · 보완 요청 · 반려), 긴급작업 접수, 공지 등록(선택) 4종이며, 템플릿 문안은 당사가 작성해 S2에 검수를 신청합니다. 작업 배정 알림에는 작업 내용과 착용해야 할 안전장비, [작업 확인하기] 링크를 포함합니다.
  • 모든 발송은 발송 이력 테이블에 남습니다. 재시도 가능한 실패는 G1에서 합의한 횟수·간격으로 재발송하고 중복 발송을 방지하며, 최종 실패와 결과 미확인 건을 구분해 관리자 화면에 표시합니다. 전달 결과만으로 실제 열람을 단정하지 않습니다.
  • 문자(SMS) 대체 발송은 선정 대행사의 지원 여부·API·계약·발신번호 등록 조건을 확인하고 발주처 승인 후 적용합니다. 별도 구현이 필요한 경우 추가 공수와 발송료를 안내하며, 발송료는 견적에서 제외합니다.
  • 현장에서 긴급작업을 접수하면(모바일 웹, 사진 첨부 가능) 해당 현장의 작업관리자 · 안전관리자에게 알림톡 발송을 즉시 요청하고 대시보드 상단에 고정 표시합니다. 실패 시 직접 연락할 수 있도록 결과를 표시합니다.
  • 접수 → 조치 중 → 조치 완료 상태와 조치 결과 기록을 남깁니다. 「조치 중」으로 변경하는 것만으로 실제 작업 착수가 승인되지는 않습니다. 실제 작업이 필요하면 작업 등록으로 연결하고, 안전 확인과 작업관리자 승인을 거친 뒤 착수합니다. 허가 대상 작업은 작업허가 조건도 충족해야 합니다. 긴급 상황의 연락·초기 대응 및 작업 연결 절차는 G1에서 확정합니다.
  • 공지사항 — 고객사 전체 / 현장별 / 협력업체별로 대상을 지정해 게시하고, 상단 고정과 게시 기간을 설정합니다. 작업자 모바일 화면 첫 단계에서 미확인 필독 공지를 보여 줄 수 있습니다.
  • 비상연락망 — 현장별 비상 연락처(안전관리자 · 소방 · 병원 등)를 관리하고, 작업자 모바일 화면에서 누르면 바로 전화가 걸리는 링크로 보여 줍니다. 휴대전화번호는 권한이 있는 역할에게만 전체 번호를 표시합니다.
  • 기본안으로 테스트 서버(53일차, G3)와 운영 서버(82일차, G4)를 발주처 명의 AWS 계정에 구축합니다. 당사는 계정 소유자 자격이 아니라 발주처가 발급한 작업 권한(IAM)으로만 작업합니다.
  • 두 서버를 같은 Docker 이미지로 배포하고, DB 자동 백업(7일 보관, 특정 시점 복원)과 서버 · DB · 디스크 · 인증서 만료 감시 알림을 설정합니다. 사진·첨부는 G1에서 확정한 복구 정책을 적용하고 삭제·덮어쓰기 샘플 복구로 검증합니다.
  • 상태 이력 — 작업 · 허가 · 서류 · 긴급작업의 모든 상태 전이를 수행자 · 시각 · IP와 함께 저장합니다. 감사 로그 — 로그인 · 권한 거부 · 서류 내려받기 · 관리자 설정 변경을 별도 로그로 남깁니다.
  • 개인정보 — 작업자 휴대전화번호는 암호화해 저장하고 화면에는 가운데를 가려 표시합니다. 전송 구간은 모두 HTTPS입니다. 개인정보 처리방침 문안은 발주처가 확정하고, 당사는 화면 게시 위치를 제공합니다.

유상 유지보수 — 2안

A. 월 정액형
1,000,000원 / 월 (부가세 별도)

운영 관리 2.0 MD + 기능 개선 2.0 MD. 월 2.0 MD 안에서 별도 견적 없이 처리합니다(양식 1종 추가 1.5 MD 기준으로 월 1종 정도). 기능 개선 공수만 다음 달로 1개월까지 이월하며, 이월분부터 사용하고 재이월은 하지 않습니다.

맞는 경우 양식 개정 · 현장 추가 등 작은 변경이 매달 생길 때 · 계약 단위 6개월 단위, 1개월 전 통보로 B안 전환 가능

B. 건별 견적형
500,000원 / 월 (부가세 별도) + 건별 견적

운영 관리만 월 정액으로 두고, 기능 변경은 건마다 250,000원/MD 기준으로 견적 → 승인 후 착수합니다.

맞는 경우 변경이 가끔, 한꺼번에 생길 때 · 계약 단위 월 단위

두 안 모두 인프라 이용료·알림톡 발송료는 별도입니다. 운영 관리 한도는 위 운영 관리비 안내를 따르며, A안의 기능 개선이 월 배정·유효 이월 공수를 초과하면 추가 견적을 승인받은 뒤 착수합니다. 작업 내역과 실제 사용 공수를 월간 보고서에 기록하고, 우선순위·배포 일정 및 계약 종료 시 잔여 공수 처리 방식은 계약 전에 합의합니다.
